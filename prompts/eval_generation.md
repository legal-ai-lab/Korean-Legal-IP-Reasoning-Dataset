학습셋(SFT·DPO)과 **근거 단위로** 분리한다. 같은 판례의 다른 문장으로 바꿔 묻는 것도 누수로 본다.

| 구분 | 평가 전용 근거 |
|---|---|
| Precedent Conflict | 2013후37, 2017후2819, 2012후2463, 2011후3698 (판례 변경 확정 15건 중 4건 보류) |
| Rule-Precedent Exception | 2023후11562, 2022다209079, 2024다311181, 2023다285162, 2020후11479 |
| Standard(조문) | 특허법 제36·37·88·99·103조, 상표법 제35·93·98·150조, 민법 제104·108·110·139·398조 |
| Standard(판례) | 2017후1304, 2022후10210, 2024후10825, 2022후10289, 2020후11943, 2021도2180, 2025다219495, 2024다228630 |

## 프롬프트
```
아래 원문만을 근거로 OX 평가 문항 {N}개를 만드시오.

[원문]
{SOURCE}

[규칙]
- 자동 채점이 가능하도록 정답이 O 또는 X로 명확히 갈리는 단일 명제로 쓴다.
- precedent_conflict: 같은 판례로 '변경 후 법리(O)'와 '종전 판례 관점(X)' 문항을 모두 만든다.
- rule_precedent_exception: 조문 문언만 보면 반대 결론이 나오는 지문을 포함한다.
- rationale에 정답 근거를 1문장으로 남긴다(에러 분석용).

[출력 스키마]
{"id": "...", "category": "...", "law": "...", "statement": "...", "answer": "O|X",
 "sources": ["특허법 제36조 제1항" | "사건번호"], "rationale": "..."}
```

## 자동 검수
`src/build_dataset.py`가 평가셋 근거 판례·조문이 학습셋 근거와 겹치지 않는지, 지문이 학습셋과 동일하지 않은지 검사한다(`data/build_report.json`의 `leak_check`).
